Product page and cart

The product template is assembled from blocks, which means the order of the page is yours to change in the editor rather than in code. This page covers that order, the variant picker, structured data and how the cart drawer decides to open.

Block order

Everything below is a block inside the Product section. Up to 30 blocks are allowed; the single-use blocks are marked with their limit. The shipped order is vendor, title, price, variant picker, buy buttons, stock, details, share.

One of each

Single-use blocks cannot be duplicated in the editor — the button is simply absent. If you need the same content twice, use a text block instead of a second title or description.

Variants, stock and prices

None of this is stored in the theme. The variant picker reads product.options; the price block reads the selected variant's price and compare_at_price; the stock block reads inventory_quantity and inventory_policy. Practical consequences:

  • A variant that continues selling at zero stock shows the in-stock line, because Shopify allows the sale. That is Shopify's rule, not the theme's.
  • Unit prices appear only when the product has a unit price measurement set in admin.
  • Changing a price in admin changes the storefront without touching the theme.

Structured data

The product section outputs Product JSON-LD so search engines can read price, availability and currency. It is on by default (show_jsonld). Leave it on unless another app is already emitting Product markup — two competing blocks of JSON-LD on one page is worse than none.

Related pieces

show_related adds a strip of products from the same collection below the product, with related_limit controlling how many. Shopify chooses which products; the theme only decides how they look. On a product that belongs to no collection, the strip does not render.

The cart drawer

With enable_cart_drawer on, adding a product posts to Shopify's cart API and opens a drawer instead of navigating away. The drawer lists line items with quantity steppers, a subtotal, and a link to the full cart page.

The bag icon in the header always links to /cart. That is deliberate: the drawer is an accelerator, not a replacement, and it must be possible to reach the cart with a keyboard and with JavaScript disabled.

Cart page

The cart page is a separate template and stays reachable regardless of the drawer. Its settings are copy only — heading, subheading, the empty-bag message, and an optional note about how checkout is handled.

show_note toggles the note block; note is the text inside it. Keep that text factual: it sits directly above the checkout button, where customers are most likely to read it.

Two global settings also land here

The product page reads pdp_stock_text and pdp_shipping_text from Product and details for its shipping accordion, so the same sentence appears on the home-page product panel and on every product page. Edit it once, in the global settings.
